# reference/

Input artifacts. These are requirements and specifications
the build was written against, not outputs of it.

Nothing here is generated by the scripts. If a number in the
database disagrees with a file in this folder, the file is
the requirement and the database is wrong, with one
exception noted below.

---

## Requirements

**business_metrics_master_comprehensive_mortgage_recreated.xlsx**
The mortgage business metrics inventory that drove the
architecture. 220 metrics with business definitions, domains
and stakeholder teams.

This workbook is the reason the source layer has 10 systems
rather than one loan table. Each metric was resolved to the
source domain that would legitimately own it, and domains
with no metric behind them were not built. The resulting
assignment is `docs/METRIC_COVERAGE_MATRIX.md`.

The workbook's definitions are business descriptions, not
calculation specifications. Converting them into numerator,
denominator, grain, population, inclusion and exclusion
logic is the work recorded in `gov.MetricDefinition`.

## NMLS Mortgage Call Report FV7

**MCR_FV7Definitions.pdf**
NMLS official field definitions and filing instructions.
Authoritative for what each line item means. The instruction
text seeded into `gov.RegulatoryReportItem` comes from here.

**MCR_FV7Sample.xlsx**
NMLS sample workbook. Input to `build_catalog.py` alongside
the FV7 XSD. Supplies item labels and the item-to-element
pairing the generated catalog depends on.

**MCR_FV7_Data_Dictionary.xlsx**
Field-level dictionary for FV7.

**MCR_Sample_FV6.xlsx** and **MCR_Data_Dictionary.xlsx**
Prior form version. Retained for the version diff procedure
in `docs/mcr/MCR_FV7_Master_SOP.docx` and for effective-date
questions about periods filed on the older form.

**model_v7.json**
Generated model of the FV7 catalog, emitted by
`build_catalog.py`. This is the one file here that is an
output rather than an input. It lives with the reference set
because it is the diff basis for a future form version.

The FV7 XSD itself is shipped by NMLS and is not
redistributed in this repository. Obtain it from NMLS before
regenerating the catalog.

## Mapping and governance workbooks

**MCR_Toolkit_Source_Mapping_Workbook.xlsx**
Item to source mapping worked out before the SQL existed.
Superseded in the database by `gov.RegulatoryMapping` and
`reg.McrElementLineage`, and retained as the working paper
that shows the mapping decisions were reasoned rather than
inferred.

**MCR_Toolkit_Governance_Log.xlsx**
Change log for the filing engine. Superseded in the database
by `gov.ChangeLog` for anything the governance platform owns.

Where a workbook and the database disagree, the database is
current. These are kept as provenance, not as a second system
of record.

## filings/

**MCR_Toolkit_filing_1001_sample.xml**
Sample FV7 batch file produced by the engine.

**MCR_Toolkit_filing_full_coverage_demo_v7.xml**
Full-coverage XML with every catalog element populated. This
is the schema coverage proof: it is validated against the
NMLS XSD after any form upgrade, because it is the only
artifact that exercises every element path.

Neither file contains real borrower, loan or company data.
